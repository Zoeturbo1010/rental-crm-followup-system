# 客户跟进系统：业务流转与验收

## 产品边界

面试作品集，虚构客户与房源，所有业务记录保存在访问者当前浏览器。没有外部消息发送、真实房源接口或多人云同步。到期提醒在页面打开期间每 15 秒更新，并在重新聚焦页面时刷新；关闭页面后不会发送系统、飞书或短信推送。

## 状态规则

| 动作 | 客户阶段 | 同步结果 |
| --- | --- | --- |
| 新增客户 | 待跟进 | 建立档案事件与首次跟进任务；姓名、电话、下一次时间必填，校验重复电话 |
| 保存人工跟进 | 无有效预约时转待推荐 | 保留每次内容、时间、负责人、意向与沟通方式，完成上一轮任务并生成下一轮 |
| 推荐房源 | 待推荐；有预约则保持待看房 | 选择可租房源、保存房源 ID 与推荐备注、生成反馈任务 |
| 创建预约 | 待看房 | 关联原客户、房源、集合地点、带看人；检查前后 1 小时客户/带看人冲突 |
| 预约确认 | 保持待看房 | 关闭该预约的二次确认提醒，预约时间到后提醒带看 |
| 预约改期 | 保持待看房 | 更新原记录并恢复待确认；旧时间不再触发提醒 |
| 取消预约 | 无其他有效预约则恢复待推荐 | 保存原因，创建后续跟进；不能把客户标为已看房 |
| 完成带看 | 已看房、待推荐；若还有有效预约保持待看房 | 仅已确认且时间已到的预约可完成；填写真实反馈，建立回访任务 |
| 看房后跟进 | 待推荐或保留有效预约 | 关闭上一轮回访，保留时间线；支持二次推荐或再预约 |
| 创建成交 | 已成交 | 仅已看房客户可成交；保存输入的租金/佣金/已收金额；关闭售前任务与剩余预约，关联房源标已租 |
| 编辑成交/结算 | 保持已成交 | 更新原成交 ID，不增加成交数量；根据实际已收金额计算待结算、部分结算、已结算 |
| 成交后关怀 | 保持已成交 | 可选安排独立关怀待办；不重开售前任务 |
| 别处成交 | 已流失 | 不生成本平台成交；关闭任务和预约，保留档案与流失原因 |
| 重新激活 | 待推荐 | 保留旧记录，新增激活事件和明日跟进任务 |

“未看房/已看房”描述实际看房经历，“待跟进/待推荐/待看房/已成交/已流失”描述当前流程。已看房客户可以再次待看房。历史看房可在档案中补录，已有实际完成带看或成交记录时不能改回未看房。

档案标签编辑不是人工跟进，不累计沟通次数；流程状态不存入可随意切换的标签。业务通过统一的纯函数 `transition` 原子更新，失败时原状态不变。通知是有效任务的派生视图，不单独累积字符串，也不靠过期标签判断。

## 统计口径

- 漏斗：筛选指定时段入库的同一批客户，观察截至现在的累计进展，关联客户去重；历史看房及下游记录可证明前序环节。待推荐本身不等于已发送推荐。
- 期间活动：人工跟进按沟通时间，带看按完成时间，成交按成交时间。
- 当前任务：实时库存，区别于期间活动；规则开关过滤通知但不删除待办。
- 流失：已标记别处成交；预算等标签为活跃阻塞原因，不能等同流失。
- 历史无确切时间的客户/记录在“全部”中保留，不伪造入库与事件时间，也不混入期间统计。
- 佣金：应收、实际已收、余额分别计算；已收不能大于应收。

## 旧数据迁移

首次访问优先读取 `customer-followup-v3`。若没有，尝试将 `rental-crm-demo-flow` 迁移至统一结构，并保留原键作为原始副本。保留历史跟进内容和原文字时间；按姓名或原客户 ID 修复孤立成交关联，必要时生成历史客户档案；修正“已有预约仍待跟进”等不一致状态。不自动读写两个公网域名间的浏览器数据。

## 验证

`npm test` 覆盖新增到成交结算、时间到期及清除、重复客户/成交、冲突预约、取消/改期、历史迁移、阶段保持、售后任务及统计日期边界。`npm run typecheck:crm` 检查实际运行入口与业务模块。发布前另运行生产构建和浏览器主链路验证。
